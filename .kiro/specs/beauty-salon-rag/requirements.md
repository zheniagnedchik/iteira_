# Требования к RAG-системе для поиска услуг салона красоты

## Введение

Система предназначена для поиска услуг салона красоты и консультирования клиентов. Система использует двухэтапный подход: первый GPT ищет релевантные услуги в облегченном файле, второй GPT отвечает на вопросы клиентов на основе найденных услуг с полной информацией.

## Требования

### Требование 1

**Пользовательская история:** Как клиент салона, я хочу найти подходящие услуги по моему запросу, чтобы получить информацию о процедурах, ценах и мастерах.

#### Критерии приемки

1. КОГДА пользователь вводит запрос о услуге ТОГДА система ДОЛЖНА найти релевантные услуги в файле services_no_staff.json
2. КОГДА найдены релевантные услуги ТОГДА система ДОЛЖНА получить полную информацию из services.json включая данные о мастерах и датах
3. КОГДА получена полная информация ТОГДА система ДОЛЖНА предоставить консультацию или помочь с записью на процедуру

### Требование 2

**Пользовательская история:** Как разработчик, я хочу иметь модульную архитектуру системы, чтобы легко модифицировать и поддерживать код.

#### Критерии приемки

1. КОГДА создается система ТОГДА она ДОЛЖНА быть разделена на отдельные модули для поиска и консультирования
2. КОГДА модифицируется логика ТОГДА изменения ДОЛЖНЫ затрагивать только соответствующий модуль
3. КОГДА запускается приложение ТОГДА оно ДОЛЖНО работать без дополнительных зависимостей типа Docker

### Требование 3

**Пользовательская история:** Как система поиска, я хочу эффективно находить услуги по текстовому запросу, чтобы предоставить точные результаты.

#### Критерии приемки

1. КОГДА поступает запрос ТОГДА первый GPT ДОЛЖЕН проанализировать services_no_staff.json и вернуть массив ID релевантных услуг
2. КОГДА получены ID услуг ТОГДА система ДОЛЖНА найти соответствующие записи в services.json по полю "id"
3. КОГДА найдены полные записи ТОГДА система ДОЛЖНА передать их второму GPT для формирования ответа

### Требование 4

**Пользовательская история:** Как клиент, я хочу получать консультации о процедурах или помощь с записью, чтобы принять обоснованное решение.

#### Критерии приемки

1. КОГДА задается консультационный вопрос ТОГДА система ДОЛЖНА предоставить информацию о процедурах, показаниях, противопоказаниях
2. КОГДА клиент хочет записаться ТОГДА система ДОЛЖНА показать доступных мастеров и даты из поля "staff" и "booking_dates"
3. КОГДА предоставляется информация ТОГДА она ДОЛЖНА включать цены, длительность и место оказания услуг

### Требование 5

**Пользовательская история:** Как администратор системы, я хочу легко запускать и настраивать приложение, чтобы быстро развертывать систему.

#### Критерии приемки

1. КОГДА запускается приложение ТОГДА оно ДОЛЖНО работать как простое Python приложение без контейнеризации
2. КОГДА нужно изменить настройки ТОГДА они ДОЛЖНЫ быть доступны в отдельном конфигурационном файле
3. КОГДА происходит ошибка ТОГДА система ДОЛЖНА предоставить понятные сообщения об ошибках
