# Рефакторинг оркестратора диалогов

## Что было сделано

### 1. Создан GPT-оркестратор (`beauty_salon_rag/gpt_orchestrator.py`)
- Новый модуль, который использует GPT для принятия решений о диалоге
- Управляет контекстом пользователей
- Выполняет различные действия (приветствие, показ услуг, подтверждение записи и т.д.)
- Использует готовый метод `orchestrate_dialog` из `GPTClient`

### 2. Упрощен основной оркестратор (`beauty_salon_rag/dialog_orchestrator.py`)
- Удален весь сложный код управления состояниями
- Удалены паттерны распознавания намерений
- Удалены классы `DialogState` и `UserProfile`
- Теперь просто делегирует всю работу GPT-оркестратору
- Сократился с ~1000+ строк до ~80 строк

### 3. Основные преимущества
- **Простота**: Код стал намного проще и понятнее
- **Гибкость**: GPT принимает решения динамически, а не по жестким правилам
- **Меньше багов**: Меньше кода = меньше места для ошибок
- **Легкость поддержки**: Проще добавлять новые функции

### 4. Что осталось
- Методы для совместимости: `get_user_stats`, `clear_user_context`, `get_orchestrator_stats`
- Основной метод `process_message` - теперь просто вызывает GPT-оркестратор
- Логирование и обработка ошибок
