# RAG-система для поиска услуг салона красоты

Интеллектуальная система поиска и консультирования по услугам салона красоты, использующая технологию RAG (Retrieval-Augmented Generation) с двухэтапным подходом обработки запросов.

## 🌟 Особенности

- **Двухэтапный поиск**: Первый GPT ищет релевантные услуги в облегченном файле, второй предоставляет детальную консультацию
- **Интеллектуальные консультации**: Подробные ответы о процедурах, показаниях, противопоказаниях и записи к мастерам
- **Модульная архитектура**: Легко расширяемая и поддерживаемая система
- **Обработка ошибок**: Централизованная система обработки ошибок с информативными сообщениями
- **Логирование**: Подробное логирование всех операций для мониторинга и отладки
- **Интерактивный интерфейс**: Удобный чат-интерфейс для взаимодействия с пользователями
- **Оптимизация производительности**: Кэширование ответов, retry-логика, настройки производительности
- **Различные режимы работы**: Режимы разработки, тестирования и продакшена
- **Простой запуск**: Автоматизированные скрипты запуска с проверкой системы
- **Полное тестирование**: Комплексное системное тестирование с реальными данными
- **Telegram бот**: Интерфейс через мессенджер с поддержкой контекста диалогов

## 📋 Требования

- Python 3.8+
- OpenAI API ключ
- Зависимости из `requirements.txt`

## 🚀 Быстрый старт

### 1. Установка

```bash
# Клонирование репозитория
git clone <repository-url>
cd beauty-salon-rag

# Установка зависимостей
pip install -r requirements.txt
```

### 2. Настройка

Создайте файл `.env` в корневой директории (используйте `.env.example` как шаблон):

```env
# OpenAI API настройки
OPENAI_API_KEY=your_openai_api_key_here
OPENAI_MODEL=gpt-3.5-turbo
OPENAI_MAX_TOKENS=1000
OPENAI_TEMPERATURE=0.7

# Файлы данных
SERVICES_FILE=services.json
SERVICES_NO_STAFF_FILE=services_no_staff.json

# Логирование
LOG_LEVEL=INFO

# Настройки приложения
DEBUG=False
APP_MODE=production  # development, testing, production
INTERACTIVE_MODE=True

# Настройки производительности
PERFORMANCE_MODE=balanced  # speed, quality, balanced
ENABLE_CACHING=True
CACHE_TTL=300  # Cache TTL в секундах
MAX_RETRIES=3
REQUEST_TIMEOUT=30
```

### 3. Подготовка данных

Убедитесь, что в корневой директории есть файлы:
- `services.json` - полные данные об услугах с информацией о мастерах
- `services_no_staff.json` - облегченные данные для быстрого поиска

### 4. Запуск

#### Простой запуск (рекомендуется)

```bash
# Автоматическая проверка и запуск
python start.py

# Или используйте скрипты для вашей ОС
./start.sh    # Linux/macOS
start.bat     # Windows
```

#### Различные режимы запуска

```bash

python start.py --check

# Быстрые тесты
python start.py --test

# Полное тестирование
python start.py --full-test

# Одиночный запрос без интерактивного режима
python start.py --query "массаж лица"

# Режим разработки
python start.py --mode development

# Быстрый режим производительности
python start.py --performance speed

# Режим качества
python start.py --performance quality
```

#### Прямой запуск

```bash
# Традиционный способ
python main.py
```

#### Telegram бот


### Модули

#### 1. Главный модуль (`main.py`)
- Координация работы всех компонентов
- Интерактивный чат-интерфейс
- Обработка пользовательских запросов

#### 2. Поисковый модуль (`search_module.py`)
- Поиск релевантных услуг через GPT
- Работа с облегченными данными
- Валидация результатов поиска

#### 3. Консультационный модуль (`consultation_module.py`)
- Генерация детальных ответов
- Форматирование информации о мастерах
- Обработка запросов на запись

#### 4. GPT клиент (`gpt_client.py`)
- Взаимодействие с OpenAI API
- Специализированные промпты для поиска и консультаций
- Обработка ошибок API

#### 5. Загрузчик данных (`data_loader.py`)
- Загрузка и кэширование JSON файлов
- Поиск услуг по ID
- Валидация данных

#### 6. Система логирования (`logger.py`)
- Структурированное логирование операций
- Декораторы для автоматического логирования
- Производительность и отладка

#### 7. Обработка ошибок (`error_handler.py`)
- Централизованная обработка исключений
- Пользовательские сообщения об ошибках
- Категоризация ошибок по типам

## 📝 Логирование

Система использует структурированное логирование с несколькими уровнями:

- **DEBUG**: Детальная отладочная информация
- **INFO**: Общая информация о работе системы
- **WARNING**: Предупреждения о потенциальных проблемах
- **ERROR**: Ошибки, не критичные для работы системы
- **CRITICAL**: Критические ошибки, требующие немедленного внимания

Логи сохраняются в директории `logs/` с автоматической ротацией.

## 🚨 Обработка ошибок

Система включает централизованную обработку ошибок с категоризацией:

- **SYSTEM**: Системные ошибки (файлы, конфигурация)
- **API**: Ошибки внешних API (OpenAI)
- **DATA**: Ошибки данных (некорректный JSON, отсутствующие поля)
- **USER**: Ошибки пользовательского ввода
- **BUSINESS**: Бизнес-логические ошибки
